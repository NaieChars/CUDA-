Shared GEMM：加载、复用、同步

返回练习 04 · 朴素版速查

三个坐标空间

T=16，block=(16,16)。row=blockIdx.y×T+ty，col=blockIdx.x×T+tx；段起点 k0=0,T,2T…。线程输出归属不变，加载坐标与计算时读取的坐标不同。

用途global / shared 关系合法条件
加载 As[ty,tx]a[row*k+k0+tx]row<m && k0+tx<k
加载 Bs[ty,tx]b[(k0+ty)*n+col]k0+ty<k && col<n
段内累加sum += As[ty,e]*Bs[e,tx]e=0…T−1，尾部已补零
最终写出c[row*n+col] = sumrow<m && col<n

shared 也按行主序展开，行宽 T。单个 extern 数组前 T² 个 float 为 As，后 T² 个为 Bs；本框架启动时已经传入 2048 字节动态 shared。

同步不变量

每一段所有 shared 槽位都写入有效值或零，再由第一道 block 屏障发布。所有线程读完本段后，经过第二道 block 屏障，下一段才可覆盖。sum 私有且跨段保留；不同线程不归约、不原子加。所有线程都执行同样的 K 段和屏障；本实现不提前 return，只在最终写 C 时裁剪输出。

__global__ void sgemm_shared(const float* __restrict__ a,
                             const float* __restrict__ b,
                             float* __restrict__ c,
                             size_t m, size_t n, size_t k)
{
    constexpr int T = sgemm_config::kSharedTile;
    extern __shared__ float smem[];
    float* as = smem;
    float* bs = smem + T * T;
    const size_t tx = threadIdx.x;
    const size_t ty = threadIdx.y;
    const size_t row = static_cast<size_t>(blockIdx.y) * T + ty;
    const size_t col = static_cast<size_t>(blockIdx.x) * T + tx;

    float sum = 0.0f;
    for (size_t k0 = 0; k0 < k; k0 += T)
    {
        as[ty * T + tx] = (row < m && k0 + tx < k)
            ? a[row * k + k0 + tx] : 0.0f;
        bs[ty * T + tx] = (k0 + ty < k && col < n)
            ? b[(k0 + ty) * n + col] : 0.0f;

        __syncthreads();
        for (int e = 0; e < T; ++e)
            sum += as[ty * T + e] * bs[e * T + tx];
        __syncthreads();
    }

    if (row < m && col < n)
        c[row * n + col] = sum;
}

性能假设的边界

完整 T×T 输出 tile 的一段 K：T³ 次乘加，global 输入标量读取由源码层面 2T³ 次变成 2T² 次。T=16 时从 8192 次变为 512 次。此计数不包括 C 写回，也不是缓存后 DRAM 字节统计；尾部会有无效线程和补零乘加。shared 版引入 shared 读写和 block 屏障，是否加速必须实测。

先建立显式输入复用，不套用转置的自动加一列 padding，也不预设 bank conflict 是瓶颈。后续按实际访问地址与 profiler 数据诊断；本节不扩展到寄存器分块、异步拷贝或 Tensor Core。

依据：官方 tiled MatMulKernel · 同步规则 · 输入复用案例。尾部处理、动态 shared 布局和计数按本项目接口推导。
