查看 sgemm_naive 参考实现
__global__ void sgemm_naive(const float* __restrict__ a,
                            const float* __restrict__ b,
                            float* __restrict__ c,
                            size_t m, size_t n, size_t k)
{
    const size_t row = static_cast<size_t>(blockIdx.y)
                     * blockDim.y + threadIdx.y;
    const size_t col = static_cast<size_t>(blockIdx.x)
                     * blockDim.x + threadIdx.x;
    if (row >= m || col >= n)
        return;

    float sum = 0.0f;
    for (size_t p = 0; p < k; ++p)
        sum += a[row * k + p] * b[p * n + col];

    c[row * n + col] = sum;
}

先检查这四处

A 的行宽是 K，B/C 的行宽是 N；grid.x 对应 col；每个 sum 都从 0 开始；输出使用赋值，覆盖旧 C。n=1 或 K 非整除都不需要特殊求和逻辑，本版的 p 循环只遍历真实 K。

访存判断

项目 block=(16,16)，一个 warp 跨两行。固定 p 时，每半个 warp 读取相同的 A 元素，B 为连续的 16 个值，另一半 warp 读取相同的 B 地址组。跨 p 的单线程跨度不直接决定跨 lane 的合并情况；缓存命中和 DRAM 流量留给测量。

符号与数值

本实验是行主序 FP32 的 C=AB。通用 GEMM 常含 alpha、beta 和转置选项，本阶段接口不含这些扩展。按常用口径，吞吐分子为 2MNK FLOP；源码里的 sum += a*b 可能被编译器融合为 FMA，具体指令由编译结果决定。

原始依据：官方矩阵乘法与行主序示例 · 合并访存说明 · 后续复用背景。warp 地址模式与尾部处理是结合本项目配置进行的推导。
