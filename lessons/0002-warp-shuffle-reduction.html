一步：32 个线程怎样交换值？

本项目的一维 block 每连续 32 个线程组成一个 warp；warp 内位置叫 lane，范围为 0～31。lane = tid % 32，warp_id = tid / 32。

float other = __shfl_down_sync(0xffffffffu, sum, offset);

这条指令取得同一 warp 中 lane+offset 的 sum，通过寄存器通信，无需先写 shared memory。它只返回对方的值，加法仍由 sum += other 完成。若 lane+offset 超出默认宽度 32，则返回当前线程自己的值；因此最终只使用 lane 0 的完整和，不把其他 lane 的返回值都当作总和。官方语义。

__device__ __forceinline__ float warp_sum(float value)
{
    for (int offset = 16; offset > 0; offset >>= 1)
        value += __shfl_down_sync(0xffffffffu, value, offset);
    return value;  // 完整总和位于 lane 0
}

把 helper 定义在 kernels.cu 的核函数之外、reduce_shuffle 之前。__device__ 表示 GPU 调用，__forceinline__ 是编译器内联指示。本节推荐先读 NVIDIA Using CUDA Warp-Level Primitives 的 Listing 1。

跟踪 1～32 的求和

每次前进一步完成一个 offset。只展示仍通向 lane 0 总和的有效前缀；点号表示该位置不再用于后续结果，不代表线程退出或不执行 shuffle。

练习 1：线程 tid=77 属于哪个 warp、哪个 lane？

full mask 表示哪些线程参加

0xffffffffu 的 32 个二进制位均为 1，表示 warp 的 32 个 lane 都参加。它不是“32 个输入有效”的标志。本节保持每个 warp 的 32 个线程都执行 helper；没有有效输入的线程提供 0。block 是 [32,1024] 内的 2 的幂，因而不存在物理上不足 32 个线程的最后一个 warp。

不要把 helper 放进 if (idx < n)、if (lane < offset) 或 if (lane < num_warps)，也不要提前 return。被 mask 指定的线程必须执行相应 shuffle，来源 lane 也必须参与。参与规则。

两步：跨 warp 仍然用 shared memory 接力

B=256 时有 8 个 warp，每个 warp 各自得到一个总和，shuffle 无法直接跨 warp 读取。解决方法：

256 个线程局部和
  ↓ 各 warp 全部 32 个 lane 执行 warp_sum
8 个 warp 和，分别位于各自的 lane 0
  ↓ 各 lane 0 写 warp_sums[warp_id]
所有 block 线程执行一次 __syncthreads()
  ↓ warp 0 的 lane 0～7 读取 8 个和，其余 24 个 lane 提供 0
warp 0 全部 32 个 lane 再执行 warp_sum
  ↓
线程 0 写 partial[blockIdx.x]

第二次调用可以放在 if (warp_id == 0) 中，因为它选中完整的一个 warp；不能只让其中 8 个线程调用。shuffle 的 sync 不提供 shared memory 的内存屏障，所以两级间的一次 block 屏障必须保留。内存顺序说明。

只记录预测，测量集中做

与相同 B、I 的多元素版相比，输入访问和部分和数量相同；每个 warp 只写一个 shared 槽位，再由 warp 0 读取。B=256 时，你当前基础树在加载后和 stride=128～2 后共执行 8 次 block 屏障，这份两级方案执行 1 次。

源码使用的 shared 槽位变少，但 launcher 仍预留 B×sizeof(float) 字节，不能据此声称占用下降或 occupancy 提升。减少屏障也不能直接推导加速比例。按你的安排，所有版本完成后统一做正确性检查、完整计时和 profiler 分析；本节没有性能结果。
