输出并行，K 方向在线程内累加

本实验计算 C[M,N] = A[M,K] × B[K,N]。选定输出 (row,col) 后，把 A 的第 row 行和 B 的第 col 列相乘求和：

C[row,col] = Σ A[row,p] × B[p,col]，p = 0…K−1

每个线程拥有一个独立输出，用私有 float sum 遍历 K，再写一次 C。它复用了你在多元素归约中掌握的局部累加方式。不同 C 元素之间没有本版所需的通信，因此无需 shared memory、shuffle、原子加或 block 屏障。官方朴素矩阵乘法示例采用相同的输出分工。

跟踪一个线程的局部和

高亮先标出目标行/列，随后标出本步的两个输入。C 的点号表示其他线程的输出不在当前演示范围，不表示它们应写 0。

三个矩阵，各用自己的行宽

行主序偏移为“行号 × 本矩阵列数 + 列号”。A 的行宽是 K，B 和 C 的行宽是 N，M 用于行范围判断。

逻辑元素一维数组表达式行宽
A[row,p]a[row * k + p]K
B[p,col]b[p * n + col]N
C[row,col]c[row * n + col]N

这里用 p 做循环变量，避免覆盖形状参数 k；索引采用 size_t，做 block 坐标乘法前就先转换类型。

练习 1：M=3、N=5、K=4，计算 C[2,3] 时，p=1 的 A、B 输入及最终 C 输出下标各是多少？

把线程映射到输出矩阵

框架的 block 为 (16,16)，grid.x 沿 N、grid.y 沿 M。对应关系是：

row = size_t(blockIdx.y) × blockDim.y + threadIdx.y
col = size_t(blockIdx.x) × blockDim.x + threadIdx.x

不使用整除假设；线程映射后，若 row≥M 或 col≥N，可以直接 return。本版没有后续协作屏障，因此这个提前退出成立。下一课引入 shared memory 后，要重新分析参与同步的线程集合。

编码后，用一轮 p 的地址检查直觉

不要只沿一个线程观察 B 的列访问。固定 p，考察一个完整、有效的 16×16 block 中的首个 warp：线程线性编号为 ty×16+tx，故一个 warp 跨两行。

lane输出行输出列同一 p 的 A 访问同一 p 的 B 访问
0～15rc₀～c₀+15相同 A[r,p]连续 16 个值
16～31r+1c₀～c₀+15相同 A[r+1,p]同一组连续 16 个值

所以，单线程在不同 p 上对 B 的跨度为 N，不能据此认定当前 warp 的 B 加载是跨步散读。实际 sector 数还取决于对齐、行宽与活跃 lane，不能无条件套用归约的 4 sectors/request。分析方法参考 合并访存说明；上表是对本项目 block 配置的推导。

为下一课留一个问题：哪些输入被反复使用？

固定 A[row,p]，它参与这一行的 N 个输出；固定 B[p,col]，它参与这一列的 M 个输出。下一课将显式组织 block 内的数据复用。硬件缓存和广播已经可能减少实际流量，所以源码中的重复加载次数不等于 DRAM 读取次数，也不能提前承诺 tile 大小倍数的加速。
