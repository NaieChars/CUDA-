CUDA LABS · 练习 05 · SGEMM MODE 2

四个累加器，一组外积

约 15～20 分钟。目标：每个线程负责 2×2 个输出，用两份 A 操作数和两份 B 操作数完成四次乘加，写出支持尾部的 register-tiled GEMM。

上一课：shared tiling · 速查与折叠答案 · 实验接口

sum 原本就可能在寄存器中，这次增加的是复用

上一版每个线程在一个 e 上读 A/B 各一个值，更新一个 sum。假如同一线程现在负责两行、两列的四个输出，就能读 A 的两个值、B 的两个值，交叉组合成四次乘加：

acc[0][0] += a0 * b0;    acc[0][1] += a0 * b1;
acc[1][0] += a1 * b0;    acc[1][1] += a1 * b1;

这叫一次 2×1 与 1×2 的外积。对每个 e 重复，再跨 K 段累加，最后得到四个完整点积。每个 A 操作数在本线程用两次，每个 B 也用两次；四个输出仍各有独立累加器，不做跨线程归约。CUTLASS 的 Thread-level GEMM用的就是在线程内组织寄存器复用和累加外积的思路；本课用普通 FP32 乘加实现。

把四条点积，改看成三次外积

选定的两条 A 行为 [1,2,3]、[4,5,6]，两条 B 列为 [1,3,5]、[2,4,6]。这里展示的是同一线程选中的行/列，它们在真实输出中可以相隔 16。

256 个线程，覆盖 32×32 个输出

框架保持 block=(16,16)，但 BM=BN=32、BK=16；每线程 TM=TN=2。256×4=1024，刚好覆盖一个 32×32 输出块。本课选用以下分工：

block_row = size_t(blockIdx.y) × BM
block_col = size_t(blockIdx.x) × BN
r_i = ty + i × 16，i=0,1        // block 内行号
c_j = tx + j × 16，j=0,1        // block 内列号
acc[i][j] → C[block_row+r_i, block_col+c_j]

因此 acc 是逻辑上的 2×2，四个输出在全局矩阵中并不相邻。例如线程 (tx=2,ty=3) 负责 block 内的 (3,2)、(3,18)、(19,2)、(19,18)。每个 block 内坐标 (r,c) 都能唯一反推 ty=r%16、i=r/16、tx=c%16、j=c/16，故没有遗漏或重写。

这个分工让固定 i、j 时的连续 tx 对应连续输出列，保留每半 warp 的连续写出地址。当前 16×16 block 的 warp 仍跨两行，不据此承诺完整 warp 的 sector 数。也可以设计连续小块的线程分工，但加载、计算、写回必须使用同一套坐标；本课先固定一种。

练习 1：tx=2,ty=3，acc[1][0] 对应的 block 内行、列是多少？

搬运分工独立于输出分工

本段 As[BM,BK] 有 32×16=512 个元素，Bs[BK,BN] 有 16×32=512 个元素；共需 4096 字节动态 shared，框架已经预留。256 个线程平均各搬两个 A 和两个 B。不能沿用上一版“各搬一个”。

先把 shared tile 展平成一维，让线程轮流覆盖槽位。tid=ty×16+tx，NT=256，对 A/B 分别执行 q=tid,tid+NT,…：

目标q 反推 tile 行/列源 global 坐标
As[q]，q<BM×BKar=q/BK，ap=q%BKA[block_row+ar,k0+ap]
Bs[q]，q<BK×BNbp=q/BN，bc=q%BNB[k0+bp,block_col+bc]

每个 q 只归一个 tid，故每段各槽位恰好写一次。越界写零，屏障规则延续上一课。A 的行宽是 BK=16，B 的行宽是 BN=32；加载 q 的坐标不是线程所负责的 C 坐标。

练习 2：tx=2,ty=3，第二次搬运 q=tid+256。As 与 Bs 的 tile 行、列各是多少？

先读出两组操作数，再组合四个输出

// 第一屏障之后，每个 e：
a_frag[i] = As[(ty + i * 16) * BK + e];   // i=0,1
b_frag[j] = Bs[e * BN + tx + j * 16];     // j=0,1
acc[i][j] += a_frag[i] * b_frag[j];       // 四种 i,j 组合

把读取与四次乘加分开写，清楚表达“读一次、用两次”。acc 在所有 K 段之外初始化为零；a_frag/b_frag 每个 e 更新一次。每段末尾仍保留第二道屏障，保护 shared 不被下一段提前覆盖；寄存器中的私有复用不需要新增屏障。

使用编译期固定的小数组，并对 i/j 循环加 #pragma unroll，有利于编译器将元素作为独立标量处理。但源码里的局部数组不等于已经证明放进物理寄存器；动态索引、资源压力可能导致 local memory，需结合编译报告和后续 profiler 检查。官方 local memory 说明。

  1. 声明 BM/BN/BK、TM/TN、BX/BY 常量；计算 block 起点、tid，创建归零的 acc[TM][TN]。

  3. K 段循环内，用两组 q 循环加载并补零，然后执行第一道屏障。
  4. 遍历 e，读取 a_frag/b_frag，外积更新 acc；本段结束执行第二道屏障。

先留下两个可检验的预测

比较口径shared 版本版
固定一个 e，4 次乘加的 shared 标量读取4 个输出线程合计 8 次1 个线程读取 4 次后复用
固定 32×32 输出、BK=16，global 输入标量读取4 个 16×16 block，共 2048 次1 个 32×32 block，共 1024 次

第一行来自线程内复用；第二行来自更大的 block 输出 tile。都是完整 tile 下的源码标量计数，不是 profiler 请求数或 DRAM 字节。本框架第三版同时改变了这两点，因此最终三版计时不能单独隔离“纯 register tiling”的收益。

代价是更多私有状态、每线程更多工作、shared 从 2 KiB 变为 4 KiB，以及同一问题下更少的 block；四个独立累加链也为调度提供更多指令级并行机会。是否值得，要检查实测时间、寄存器/溢出与并行度。不能用“occupancy 更高”或“shared 读取减半”中的一项预判胜负。

完成标准：能解释四个输出的唯一归属、两个加载循环为何完整覆盖 shared，以及一次外积如何复用操作数。主阅读只需 CUTLASS Efficient GEMM：Thread-level GEMM 一段；不要求学习 CUTLASS API。三版实现并验证后，进入统一性能测量与因果分析。
