协作搬一块，复用十六次

先固定输出归属，再改变输入的供应方式

仍然是 block=(16,16)，线程 (ty,tx) 负责 C[row,col]，row=blockIdx.y×16+ty，col=blockIdx.x×16+tx。它的私有 sum 从 0 开始，贯穿整个 K；不同线程不合并 sum。

固定一段长度 T=16 的 K，一个完整输出 tile 要做 T³ 次乘加。朴素版按源码逐个乘加读取两个输入，共 2T³=8192 次标量输入读取；协作版只需加载 A、B 各一个 T×T tile，共 2T²=512 个标量。每个 A 值供同一输出行的 16 个线程使用，每个 B 值供同一输出列的 16 个线程使用。

这推导的是显式 global 标量读取次数，减少 16 倍；不是 DRAM 字节或加速比的承诺。缓存、warp 内重复地址处理、编译结果，以及新增 shared 读写和屏障都会影响实测。官方案例也强调避免重复传输的价值；本页数字按项目 T=16 推导。

同一个线程，有“搬运”和“计算”两个职责

把 p=0…K−1 拆成 k0=0,16,32… 的段。每段，线程 (ty,tx) 先搬运两个元素，再从 shared 读取自己输出所需的一行和一列：

职责源 / 计算式shared 偏移
搬 AA[row,k0+tx]As[ty×T+tx]
搬 BB[k0+ty,col]Bs[ty×T+tx]
算 C[row,col]Σ As[ty,e] × Bs[e,tx]，e=0…T−1ty×T+e 与 e×T+tx

注意两个 K 坐标：搬 A 时用 tx，搬 B 时用 ty；计算时两者都用 e。搬 A/B 的线程无需就是最终使用它们的线程。这正是 block 协作的意义。官方 tiled MatMulKernel给出相同分工；本实验另外补齐尾部处理。

C 的一个输出 tile
  += A[本 block 的行, 第一段 K] × B[第一段 K, 本 block 的列]
  += A[本 block 的行, 第二段 K] × B[第二段 K, 本 block 的列]
  += …

缩到 T=2，观察 K=3 如何分两段

A=[[1,2,3],[4,5,6],[7,8,9]]，B=[[1,0,2],[0,1,1],[2,1,0]]。下面只跟踪一个 block；每次点击表示整个 block 完成一个阶段，并非模拟 warp 调度。

0* 表示越界补零；× 表示该线程不写 C。先观察左上 block：第一段后 sum=[[1,2],[4,5]]，第二段后变成 [[7,5],[16,11]]。再选右下 block，观察输出越界与 K 尾部同时发生时，加载和同步仍继续。

两道屏障，保护两个不同方向的依赖

载入 As、Bs
__syncthreads();      // 本段：先写完，才能让其他线程读
读取 shared，做 T 次乘加
__syncthreads();      // 跨段：先读完，才能让下一段覆盖
回到下一段载入

第一道防止某个 warp 读到尚未由其他 warp 写好的数据。第二道防止较快的 warp 提前写入下一段，覆盖较慢 warp 仍在使用的本段数据。warp 的执行进度不保证一致，下一段加载后的第一道屏障也无法修复已经发生的覆盖。

两道屏障都置于所有线程共同执行的 K 段循环里；不要把它们放进“输出有效”的分支。这里存在跨 warp 的数据依赖，不能直接换成 __syncwarp()。最后一段之后不再覆盖 shared，理论上无需第二道屏障；当前先统一保留，便于建立清晰的正确性结构。参见 block 屏障与可见性规则。

输出无效，不代表搬运任务无效

朴素版的越界 return 在这里不能照搬。分别判断 A 与 B 的源坐标，每个 shared 槽位每段都必须写一次，有效则读 global，无效则写 0：

A 有效：row < m  且  k0 + tx < k
B 有效：k0 + ty < k  且  col < n
C 有效：row < m  且  col < n（只用于最终写回）

例如 T=16，M=17,N=19,K=18，blockIdx=(1,1)，threadIdx=(2,3)：输出是 C[19,18]，越界；但第一段要搬的 B[3,18] 有效，其他有效输出线程还要用它。提前退出会漏掉这次搬运。

K 尾段仍计算完整 T 项，用零消掉多余项。只跳过无效 global 读取而不写 shared，会残留上一段内容。例如 K=19 时第二段只有 3 个有效 K，另 13 项必须补零；sum 则不能在段间清零。
